# Heatwave Intelligence

A Linux-based mini-project for heatwave monitoring and next-day
temperature prediction. The project combines a simple Linear Regression
model with Linux system calls, file handling, process management, and
CPU-scheduling simulations.

> **Academic prototype:** The included temperature dataset is synthetic
> and the severity thresholds are illustrative. This project is not an
> official weather-forecasting or public-warning system.

## 1. Project Overview

Heatwave Intelligence processes historical maximum-temperature
observations for four regions---Mumbai, Pune, Nashik, and Thane---and
estimates the next day's maximum temperature for each region.

The program demonstrates selected Operating Systems concepts through a
single C application:

-   **Experiment 1 -- Linux system information:** retrieves
    operating-system, kernel, memory, uptime, and available disk-space
    information.
-   **Experiment 2 -- File system and file handling:** prepares project
    directories and copies the historical CSV dataset using file
    operations.
-   **Experiment 4 -- Process handling using system calls:** creates a
    child process for each regional prediction using `fork()`, runs the
    child in a selected mode using `execl()`, and collects child
    completion statuses using `waitpid()`.
-   **Experiment 6 -- CPU scheduling:** simulates Preemptive Shortest
    Job First (SRTF) and Round Robin scheduling and calculates waiting
    and turnaround times.

## 2. Features

-   Reads historical temperature observations from a CSV file.
-   Fits a simple Linear Regression model for each region using
    `day_index` as the input feature and maximum temperature as the
    target.
-   Predicts the next-day maximum temperature.
-   Assigns an illustrative severity category:
    -   **NORMAL:** below 35°C
    -   **MODERATE:** 35°C to below 40°C
    -   **HIGH:** 40°C to below 45°C
    -   **SEVERE:** 45°C or above
-   Generates forecast and advisory output files.
-   Demonstrates parent--child process creation and coordination.
-   Simulates SRTF and Round Robin scheduling and reports Gantt
    timelines, waiting time, and turnaround time.

-   Ubuntu or another Linux environment
-   GCC compiler and standard build tools

On Ubuntu / WSL2, install the compiler tools with:

``` bash
sudo apt update
sudo apt install build-essential -y
```

This application uses Linux/POSIX interfaces and is intended to be
compiled and run in Linux or WSL2, not directly in Windows Command
Prompt.

## 6. Compile and Run

Clone the repository and enter the project directory:

``` bash
git clone https://github.com/YOUR_USERNAME/heatwave-intelligence.git
cd heatwave-intelligence
```

Compile:

``` bash
gcc -std=c11 -Wall -Wextra -O2 heatwave.c -o heatwave
```

Run:

``` bash
./heatwave
```

If your project includes a working `Makefile`, you can use `make`
instead. The direct GCC command above is the build command used for this
project.

## 7. Program Menu

The application provides the following menu:

``` text
1. Run complete heatwave prediction
2. Experiment 1 - Linux system information
3. Experiment 2 - Dataset file handling
4. Experiment 4 - Multi-process prediction
5. Experiment 6 - SRTF / Round Robin scheduling
6. View previous forecast
0. Exit
```

The complete workflow runs the system-information and file-preparation
stages, then performs the selected scheduling simulation and launches
the regional prediction child processes.

### Important note about Experiments 4 and 6

Experiment 4 and Experiment 6 are related but demonstrate different
concepts:

-   **Experiment 4** demonstrates process creation, execution, and
    parent--child coordination through `fork()`, `execl()`, and
    `waitpid()`.
-   **Experiment 6** demonstrates scheduling policies through an
    application-level SRTF / Round Robin simulation.

The scheduling simulation does **not** change or replace the Linux
kernel scheduler. Linux continues to schedule the actual processes. In
the integrated workflow, the scheduling simulation is performed as a
separate stage before the child processes are launched.

## 10. Scheduling Metrics

For each simulated regional job, the program reports scheduling
information such as arrival time, burst time, completion time, waiting
time, and turnaround time.

The calculations are:

-   **Turnaround Time (TAT) = Completion Time (CT) − Arrival Time (AT)**
-   **Waiting Time (WT) = Turnaround Time (TAT) − Burst Time (BT)**
-   **Average Waiting Time = Total Waiting Time / Number of Jobs**
-   **Average Turnaround Time = Total Turnaround Time / Number of Jobs**

The burst and arrival values used in the demonstration are illustrative
scheduling units based on the prototype's job inputs; they are not
measured CPU execution times. The Gantt chart represents the scheduling
simulation, not actual Linux process execution timings.

## 11. Limitations

-   The sample temperature dataset is synthetic, not a live IMD or
    weather-station feed.
-   Linear Regression is a simple educational model and has not been
    validated for operational weather forecasting.
-   The severity thresholds are illustrative and are not official
    government or meteorological warning thresholds.
-   The prototype does not include live sensor ingestion, geospatial
    analysis, or a validated alert-delivery service.
-   The SRTF and Round Robin components are simulations at the
    application level; they do not modify Linux kernel scheduling.
-   Forecast accuracy should not be inferred from the demonstration
    output.
